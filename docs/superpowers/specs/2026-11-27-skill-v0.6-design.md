# SayMake v0.6 设计：记忆内核 + 干活 skill + 一条命令安装

日期：2026-11-27。状态：已实现，已本地提交，未推送。前一份设计见 [`2026-11-26-skill-v0.5-design.md`](2026-11-26-skill-v0.5-design.md)。

## 一、用户要的是什么

两条硬要求：

1. **性能与开放性**：用最少的 token 最大程度地完成任务；开源，谁都能下载、部署、安装。
2. **核心愿景**：帮用户在他的 AI 工具里增加记忆和规则，自进化，越用越懂他、越顺手，像贾维斯。

## 二、我先说的实话（用户已接受为前提）

| 用户想要的 | 能不能做到 | 为什么 |
|---|---|---|
| 记住用户、规矩越用越合身、经验跨项目累积、纠正变默认 | **能** | 偏好、坑、案例、规矩存成纯文本，开工先读 |
| skill 没被叫到时也生效 | **能做到一半** | 只有"每次对话开头加载"的那一小段规矩（≤12 条）常驻，靠各工具的加载机制，且各工具是否生效尚未全部验证 |
| 模型越用越聪明 | **不能** | 模型不变，只是少犯同一个错 |
| 记的东西一定对 | **不能** | 记错会一直错。所以规矩要用户点头，偏好记了要告知，可删 |

所以"贾维斯"被拆成三样东西：**记忆内核**（跨项目、跨 skill）+ **各干活的 skill**（第一个是 make-game）+ **一条命令安装**（把内核放进任何 AI 工具）。

## 三、结构

```
install.sh                 一条命令：克隆/更新仓库 → core/install.mjs
core/install.mjs           安装器：认工具、放 skill、接上"每次加载"、--dry-run、--uninstall
core/ALWAYS.md             按各人的规矩生成的那一段（不入库）
skills/saymake/            记忆内核（skill）：SKILL.md + scripts/log.mjs
skills/make-game/          干活 skill：SKILL.md、data/（库 + guide/）、references/、scripts/
tests/                     memory.test.mjs、install.test.mjs
~/.saymake/                用户本机：memory/（规矩、偏好、案例、坑、惯例、候选）、current → 仓库、backup/
```

## 四、记忆内核

三类东西，三种信任级别：

| 类型 | 自动记还是要点头 | 上限 | 存在哪 |
|---|---|---|---|
| 偏好 | 自动，但必须告诉用户 | recall 时最多带 8 条 | `memory/profile.json` |
| 坑 | 自动 | recall 时最多带 3 条 | `memory/lessons.jsonl` |
| 案例 | 自动（start / judge / feedback / resolve 留下的） | recall 时最多带 3 条 | `memory/cases.jsonl` |
| 规矩 | **先提候选，用户点头才 `accept`** | 12 条，每条 ≤60 字 | `memory/rules.json` → 写进 `core/ALWAYS.md` |
| 惯例（用户自己加进库的做法） | **先提候选** | — | `memory/conventions.json` |

- `recall --brief`：词面相似度（中文两字一组，去掉"一个""想要""游戏"这类词），带出规矩、偏好、惯例、相似案例（带结果和教训）、相关的坑。
- `propose`：同一条候选累加次数；记忆里已有（含互相包含）就不重复提。
- `accept` / `reject` / `forget`：候选、规矩、惯例、偏好、坑、案例都能删。
- `inject` / `refresh` / `doctor`：每次加载的那一段；同步到"复制粘贴"类工具（Codex）；自检各工具是否装好、是否同步。
- `cost`：统计"从开工到写代码读了多少字符"。

**和宿主自带记忆的关系**：宿主有偏好记忆（如豆包）时，规矩被接受后同时存一份进去，保证当次对话就生效；文件那份保证换工具也带得走。

|---|---|---|---|
| `SKILL.md`（协议） | 6411 | 2989 | 每次 |
| `conventions.json`（入口） | 8693 | 1697 | 每次 |
| `library list` | 1487 | 1487 | 每次 |
| `guide/signals.json` | （在入口里） | 795 | 每次 |
| `recall` | 变动 | 130–480 | 每次 |
| `show a` / `show g` | 400–700 | 400–700 | 选中才读；不输出出处网址 |

## 六、一条命令安装

`bash install.sh`（或 curl 管道）→ 需要 Node.js 18+ 和 git → `core/install.mjs`：

1. `~/.saymake/current` 指向仓库（升级 = `git pull` 后再跑一次）。
2. 生成 `core/ALWAYS.md`。
3. 对每个认出的工具：把 `skills/saymake`、`skills/make-game` **复制**到它的 skill 目录；接上"每次加载"。

| 工具 | 怎么认 | skill 放哪 | 每次加载怎么接 |
|---|---|---|---|
| Claude Code | `~/.claude` 存在 | `~/.claude/skills/` | `~/.claude/CLAUDE.md` 里加一行 `@…/core/ALWAYS.md` 引用（官方文档说支持导入） |
| Codex | `~/.codex` 存在 | `~/.codex/skills/` | 把那一段**写进** `~/.codex/AGENTS.md`（原文件先备份；规矩变了要 `refresh`） |
| 豆包（macOS） | `~/Library/Application Support/DoubaoWork/*/` 下有 `.user_skills` | 每个配置档各一份 | 工作区根目录建 `ALWAYS.md`，一行引用（**是否真被读到未验证**） |

安全规则：可重复运行（内容相同就不动）；同名但不是安装器放的（没有 `.saymake-skill` 记号）默认不碰，`--force` 才覆盖且先备份；动过的用户文件先备份到 `~/.saymake/backup/`；`--uninstall` 用备份逐字节恢复，自己建的空文件删掉；`--dry-run` 只列计划。用复制而不是链接，因为不确定各工具认不认链接。

## 七、怎么验的（结果见 `docs/skill-test.md` 第七节）

1. 原有命令结果不变：库校验通过，6 个示例与模板浏览器验收 15/15。
2. 读取量 ≤9000：自动测试 + 第六轮真做一款的 `cost`。
3. 规矩 ≤12 条、每条一句话；规矩和惯例改动先提候选；偏好和坑自动记但告知。
4. 一条命令安装：苹果电脑上 Claude Code 和豆包各装成功一次（文件到位 + doctor 通过）；是否真被读到要用户开新对话验证；Codex、Windows 标未验证。
5. 进化回路：连做 3 个项目，第 3 个开工能带出前两个至少 2 条经验（自动测试）。
6. 自动测试：`tests/memory.test.mjs` 38 项、`tests/install.test.mjs` 32 项。

## 八、没做到和没验证的

- 需要提问的路径读取量 11450，超预算 2450。
- 各工具"每次对话自动加载"是否真的生效，本会话里验不了。
- Codex、Windows 未验证；豆包两个配置档都装了，但用户平时用哪个没问。
- 复制安装意味着改了仓库要重跑 `install.sh` 才生效。
- 相似度是词面匹配，换了说法可能带不出。
- "记忆让判断变准"没有真实用户数据，第六轮的题是我自己出的。
