# 要提问的时候读（第 1 步：信号不够、没说玩法、两个方向拿不准）

问题库在 `data/guide/questions.json`，信号优先级在 `data/guide/signals.json`。原则：选项是画面，5 秒内能选；每个检查点最多 3 个问题，全程通常 3–6 个；不问技术，不问他答不上的；他已说清的不问。

## 问的例子

```
我想先确认两件事，好把它做成你脑子里的那个样子：

1. 想玩哪一种？
   A. 接水果那种：东西从上面掉，左右滑动去接
   B. 翻对对牌：翻开两张，一样就留下
   C. 打地鼠那种：东西冒出来就点它
   （或者直接说你想怎么玩）

2. 画面更像哪种？
   A. 像现在手机上的休闲游戏——圆润、干净、颜色鲜亮
   B. 像小时候的像素游戏——小方格、颜色不多、有点怀旧
   C. 像手绘绘本——纸张的感觉、线条有点歪、暖暖的

3. 玩完一局，你最想看到什么？
   A. 分数破纪录  B. 放松解压  C. 朋友间比一比
```

玩法选项从 `library.mjs list` 的玩法里挑三个差异大的；画面选项挑反差大的，每个都用 `feelsLike` 的说法。永远留一句"都不像的话直接描述给我"。

## 他答"都不像"

不要再列三个方向。用质感词追问一次："更真实一点？更简单一点？更暖一点？"这一问通常比十个方向有用。他说清了，那就是一条新的方向——合成它，他认可后加回库里。

## 他也说不清

排除法和参考物，一次一个："有没有玩过哪个游戏是那种感觉的？""肯定不要的是什么？"

## 问完复述一遍

这是帮他把画面固定下来：

```
我理解你想要的是：
- 玩法：……
- 感觉：……
- 玩的时候：手机竖屏，手指滑动，一局一分钟，……

做好了的标准（你只需要看这三条）：
1. 打开就能玩
2. 看起来就是上面说的那种感觉
3. 玩起来有反馈，手机上不乱

不对直接说，没问题我就开始做。
```

## 几条经验

- 用对比问，不用开放问。"可爱还是酷"比"你想要什么风格"有效十倍。
- 用参考物问。一个"像某某游戏"抵十个形容词。
- 先给一稿再问。对着实物说"不对"比对着空气描述容易得多。
- 答了要看得见。他选了 B，下一稿必须明显是 B。
- 他说"你定/随便/开始做"，立刻按默认做，第一稿出来再给换方向的选项。
